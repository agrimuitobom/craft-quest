# クラフトクエスト 設計仕様書

Minecraft: Education Edition（以下マイクラEE）と並べて使う、クエスト型プログラミング学習コンパニオンアプリ。

- 対象：小学校高学年〜中学生（プログラミング初学者〜中級者）
- 学習言語：MakeCode（ブロック）/ MakeCode Python
- スタック：Next.js 15（App Router）/ TypeScript / Tailwind CSS 3 / lucide-react / LocalStorage
- 版：MVP v0.1

---

## 0. 設計の基本方針

| 方針 | 具体化 |
|---|---|
| **マイクラ本体とはAPI連携しない** | 「受注 → マイクラで実行 → アプリで報告」の3ステップ。検証は「ゲーム内の観察チェック」＋「貼り付けたコードの静的チェック」の2層 |
| **答えを教えない** | ヒントは「観察 → 焦点 → 部分コード」の3段階。前段を開かないと次が開かない。NG時のメッセージも「何が足りないか」だけを伝える |
| **失敗を責めない** | 失敗回数はマイナスにしない。3回以上の報告でクリアすると「あきらめない心」バッジ |
| **やり直す理由をつくる** | ヒントなしクリアで星3＋ボーナスEXP。クリア後もヒントをリセットして再挑戦できる |
| **サーバー不要で配れる** | 進捗は端末の LocalStorage のみ。個人情報を持たない（名前は任意のニックネーム） |

## ステップ1：システムアーキテクチャ＆データ設計

### 1-1. 全体構成

```
┌──────────── 生徒の画面（左右に並べる） ─────────────┐
│  Minecraft EE + Code Builder     │  クラフトクエスト（ブラウザ）        │
│  ・MakeCodeでプログラム作成      │  ・クエスト受注 / ストーリー         │
│  ・エージェントを実行            │  ・ヒント（デバッグ道場）            │
│  ・Pythonタブからコードをコピー ─┼─▶ ・コード貼り付け＋観察チェック     │
│                                  │  ・EXP / バッジ / スキン             │
└──────────────────────────────────┴─────────────────────────────────────┘

Next.js (App Router, すべてクライアントコンポーネント)
 ├ src/data/quests.ts        … クエスト定義（JSONスキーマ準拠）
 ├ src/data/rewards.ts       … バッジ・称号・スキン・レベル表
 ├ src/lib/progress.ts       … 状態遷移（純粋関数）＋ LocalStorage 永続化
 ├ src/lib/validator.ts      … コード静的チェック
 ├ src/components/ProgressProvider.tsx … React Context で進捗を配布
 └ src/app/…                 … 画面（/, /quest/[id], /achievements）
```

状態遷移ロジックは **React から独立した純粋関数**（`startQuest`, `openHint`, `recordFailedAttempt`, `completeQuest`, `touchStreak`）にしてあるので、将来 Supabase / Firebase 等のサーバー保存に差し替える場合も `ProgressProvider` の保存部分だけを書き換えればよい。

### 1-2. クエストデータ構造

正式なスキーマは [`docs/quest.schema.json`](./quest.schema.json)、TypeScript 型は `src/types/quest.ts`。

| フィールド | 型 | 説明 |
|---|---|---|
| `id` | string | `q01-fence` 形式 |
| `area` / `tier` / `order` | enum / enum / int | マップのエリア、難易度（初級・中級・上級）、表示順 |
| `title` | string | クエスト名 |
| `mapPos` | {x,y} (%) | ワールドマップ上の位置。% 指定なので画面幅に依存しない |
| `prerequisites` | string[] | すべてクリアで解放（クエストツリーの枝） |
| `concepts` | enum[] | 学習概念タグ（順次・くりかえし・変数・条件分岐・関数・イベント・アルゴリズム） |
| `story` | {npc,text}[] | NPC の会話。目的を物語で与える |
| `objective` / `goals` | string / string[] | **目標**：一文の目的と、子ども向けの達成条件 |
| `starter.worldSetup` | string[] | マイクラ側の準備手順 |
| `starter.blocks` | BlockNode[] | **コード雛形**（ブロック表示用の木構造。`blank:true` は考えさせる空欄） |
| `starter.python` | string | **コード雛形**（Python。空欄は `______`） |
| `hints` | Hint[3] | **ヒント**：level 1 観察 / 2 焦点 / 3 部分コード |
| `validation.codeRules` | Rule[] | **検証基準①**：`contains` / `notContains` / `minCount` / `maxCount`（正規表現） |
| `validation.observations` | string[] | **検証基準②**：ゲーム内で目視確認する項目 |
| `reward` | {exp,noHintBonus,badgeId?,unlock?} | 報酬 |
| `solution` | {python,blocksNote} | 模範解答（先生モードのみ表示） |

**例（抜粋）**

```json
{
  "id": "q01-fence",
  "tier": "beginner",
  "title": "村の柵をならべよ",
  "prerequisites": [],
  "objective": "エージェントを使って、丸石ブロックを一直線に 10 個ならべよう。",
  "hints": [
    { "level": 1, "kind": "observe", "title": "まず観察しよう", "body": "今のコードを実行すると、ブロックは何個置かれた？" },
    { "level": 2, "kind": "focus",   "title": "ここに注目",   "body": "「1マス進む → 置く」のセットを何回やればいい？" },
    { "level": 3, "kind": "partial", "title": "コードのかたち", "body": "…", "snippet": "for index in range(__):\n    ..." }
  ],
  "validation": {
    "codeRules": [
      { "type": "contains", "pattern": "\\b(for|while)\\b", "message": "「くりかえし」が使われていないみたい" },
      { "type": "maxCount", "pattern": "agent\\.place\\(", "max": 1, "message": "置く命令が2回以上書かれているよ" }
    ],
    "observations": ["丸石が 10 個ならんだ", "列がまっすぐで、とちゅうで曲がっていない"]
  },
  "reward": { "exp": 100, "noHintBonus": 30, "badgeId": "loop-starter", "unlock": { "type": "title", "id": "loop-crafter" } }
}
```

#### 検証ロジック（`src/lib/validator.ts`）

1. 貼り付けコードから `#` コメントを除去（コメント内の `for` 等で通らないように）
2. `______` が残っていれば NG
3. `codeRules` を順に評価
4. `observations` がすべてチェックされていること
5. 全部 OK でクリア。NG の場合は **満たしたルールは取り消し線、満たしていないルールだけ強調** して返す

> 静的チェックは「動くこと」の証明ではないため、観察チェック（子ども自身が結果を確かめる）と組み合わせている。授業では、先生が画面をのぞいて観察チェックを確認する運用を推奨。

### 1-3. ユーザー進捗の状態遷移

```
             前提クエストをすべてクリア
  ┌────────┐ ─────────────────────▶ ┌───────────┐  受注ボタン   ┌─────────────┐
  │ locked │                         │ available │ ────────────▶ │ in_progress │◀──┐
  └────────┘                         └───────────┘                └─────────────┘   │
                                                                      │ 報告する     │ NG
                                                                      ▼             │（attempts+1）
                                                                ┌───────────┐       │
                                                                │ verifying │───────┘
                                                                └───────────┘
                                                        OK（ヒント使用）│    │ OK（ヒント0）
                                                                        ▼    ▼
                                                                ┌─────────┐  ┌──────────┐
                                                                │ cleared │─▶│ mastered │
                                                                └─────────┘  └──────────┘
                                                        再挑戦(ヒント数リセット)→ヒント0でクリア
```

- `locked` / `available` は保存せず、前提クエストの状態から **毎回導出**（クエストを追加しても整合が崩れない）
- `verifying` は検証処理中の一時状態（MVPでは同期処理のため UI 上は一瞬）
- 保存データ `UserProgress`

```ts
{
  version: 1,
  playerName: string,
  exp: number,
  quests: { [questId]: { status, hintsOpened(0-3), attempts, startedAt, clearedAt, bestExp, lastCode, language } },
  badges: string[], titles: string[], skins: string[],
  equippedTitle: string, equippedSkin: string,
  streak: { count: number, lastDate: "YYYY-MM-DD" }
}
```

LocalStorage キー：`craft-quest:progress:v1`（`version` でマイグレーション判定）

### 2-2. 子ども向けデザインガイドライン

1. **ことば**：ひらがな多め・1文を短く。ボタンは動詞（「受注する」「報告する！」「ヒントを見る」）。専門用語は初出でかっこ書き（例：「くりかえし（ループ）」）
2. **タップ領域**：すべての操作要素を 44〜52px 以上。チェックボックスは行全体がタップ可能
3. **色の意味を固定**：緑＝進める・成功、金＝次にやること・報酬、水色＝挑戦中、赤＝要確認、灰＝ロック。色だけに頼らずアイコン（🔒✓⚔👑）と文字を必ず併記
4. **ブロック色は MakeCode に合わせる**：プレイヤー=青、エージェント=オレンジ赤、ループ=緑、変数=紫…。マイクラ画面と見比べて迷わない
5. **1画面1ゴール**：ダッシュボードは「つづきから」ボタンを最も目立たせ、次の行動を1つに絞る
6. **失敗はやさしく**：NG時は「おしい！」＋小さく揺れる演出。できている項目は取り消し線で見せ、「できていること」も伝える
7. **ヒントは段階的に**：開く前に「もう少し考える？」の確認を1回だけ挟む（禁止ではなく選択）
8. **達成感は段階演出**：EXPカウントアップ → バー伸長 → レベルアップ → バッジ／解放の順に時間差で表示
9. **アクセシビリティ**：`prefers-reduced-motion` でアニメーションを停止、フォーカスリング（金色4px）、`aria-expanded` / `role=progressbar` / `role=alert` を付与、コントラスト比 4.5:1 以上
10. **フォント**：見出しは DotGothic16（ドット風）、本文は M PLUS Rounded 1c（丸ゴシックで読みやすく）

### Q1【初級】ブロック並べ：村の柵をならべよ

- **ストーリー**：夜になるとゾンビが畑をあらしに来る。畑の前に丸石の柵を10ブロック並べてほしい。
- **学習目標**：イベント（チャットコマンド）、順次、くりかえし（同じ命令を何度も書かない）
- **準備**：スーパーフラットで平地に立ち、エージェントを呼ぶ
- **雛形**：「前に1移動 → 後ろに置く」が1回だけ書かれている（実行すると1個しか置かれない）
- **ヒント**：①何個置かれた？10個と比べて何が足りない？ ②「セット」を何回？ループのなかまを探そう ③`for index in range(__):` の形とインデント
- **検証**：`on_chat("fence")`／`for|while`／`range(10)`（または `< 10`）／`agent.place` は1回まで／観察「10個」「まっすぐ」
- **模範コード**

```python
def on_on_chat():
    agent.set_item(COBBLESTONE, 64, 1)
    agent.set_slot(1)
    for index in range(10):
        agent.move(FORWARD, 1)
        agent.place(BACK)

player.on_chat("fence", on_on_chat)
```

- **発展**：二重ループで2段の壁にする／四角形に囲う（4回くりかえし＋右に回転）

### Q3【中級】ピラミッド自動建築：砂漠のピラミッドを建てよ

- **ストーリー**：砂漠の賢者「1段ごとに2マスずつ小さくなるピラミッドがあった。変数とくりかえしを使えば一瞬で建つはずじゃ」
- **学習目標**：変数、条件付きくりかえし（while）、座標と数式（規則性の発見）
- **準備**：15×15以上の平地で北を向く
- **雛形**：`while ______:`、終点座標、`size` の変化量が空欄
- **ヒント**：①段ごとの一辺と高さを表にしよう ②終点 ＝ 始点＋一辺−1（傾き・はみ出しはここ） ③`while size > __:` と `size = size - __`
- **検証**：`on_chat("pyramid")`／`blocks.fill` を使い、かつ1回だけ／`while|for`／`size` を2ずつ減らす／観察「5段」「頂上1ブロック」「中心がそろう」
- **模範コード**

```python
def on_on_chat():
    size = 9
    layer = 0
    while size > 0:
        blocks.fill(SANDSTONE,
            pos(2 + layer, layer, 2 + layer),
            pos(2 + layer + size - 1, layer, 2 + layer + size - 1),
            FillOperation.REPLACE)
        size = size - 2
        layer += 1

player.on_chat("pyramid", on_on_chat)
```

- **発展**：チャット引数（`num1`）で大きさを変える／`FillOperation.HOLLOW` で中を空洞に／各段を2段ずつ積んで背の高いピラミッドにする（二重ループ）
- **算数・数学との接続**：等差数列（9,7,5,3,1）、使用ブロック数の合計（81+49+25+9+1=165）を予想してから建てる

### Q5【上級】迷路脱出アルゴリズム：地下迷宮から脱出させよ

- **ストーリー**：かじ屋「迷路のかたちは毎回ちがう。道順を覚えさせるんじゃなく、どんな迷路でも出られるルールを教えてやってくれ」
- **学習目標**：条件分岐、センサー（detect / inspect）、関数化、アルゴリズム（右手法）、無限ループ対策
- **準備**：先生が用意した迷路（石・高さ2）または自作。ゴールの床に金ブロック。入口でエージェントを呼ぶ
- **雛形**：`is_goal()` は完成済み、`step_right_hand()` の while 条件と回転方向が空欄、結果表示の if が未記入
- **ヒント**：①紙の迷路を右手でなぞる／ぐるぐる回っていないか観察 ②順番は「右→前→左→後ろ」。まず右を向き、壁なら左へ1回ずつ戻す ③`while agent.detect(AgentDetection.BLOCK, ______):`
- **検証**：`on_chat("escape")`／`agent.detect`／`while`／`def` が2つ以上（自作関数）／`GOLD_BLOCK` 判定／上限回数（`< 300` 等）／`if`／観察「金ブロックで停止」「ゴール表示」「迷路を変えても脱出」
- **模範コード**

```python
def is_goal():
    return agent.inspect(AgentInspection.BLOCK, DOWN) == GOLD_BLOCK

def step_right_hand():
    agent.turn(RIGHT_TURN)
    while agent.detect(AgentDetection.BLOCK, FORWARD):
        agent.turn(LEFT_TURN)
    agent.move(FORWARD, 1)

def on_on_chat():
    steps = 0
    while not is_goal() and steps < 300:
        step_right_hand()
        steps += 1
    if is_goal():
        player.say("ゴール！ " + str(steps) + " 歩でした")
    else:
        player.say("見つからなかった…")

player.on_chat("escape", on_on_chat)
```

- **発展**：左手法と歩数比較／通った床に色付きブロックを置いて軌跡を可視化／壁が「島」になっている迷路では右手法が失敗することを体験 → 探索アルゴリズム（幅優先探索など）の話へ


### Q2【初級】変数：谷にかける橋

- **ストーリー**：村人「谷のはばは場所によってちがう。そのたびにプログラムを書き直すのは大変」
- **学習目標**：変数（チャットコマンドの数字 `num1`）、くりかえし回数を変数で決める（一般化）
- **雛形**：`range(10)` で書かれていて、いつも 10 マスの橋になる（動くけれど、数字を変えても長さが変わらない）
- **ヒント**：①「bridge 5」と「bridge 12」を両方ためす ②数字は `num1` に入っている ③`range(____)`
- **検証**：`on_chat("bridge")`／`def …(num1`／`range(数字)` がない／`range(num1)`（または `< num1`）／`agent.place` は 1 回まで／観察「5 マス」「書き直さずに 12 マス」「歩いてわたれた」
- **発展**：スロット 2 の柵で手すり／はば 3 マスの橋

### Q4【中級】二重ループと条件：水路つきの畑をつくれ

- **ストーリー**：村人「畑は近くに水がないとかわく。9×9 の畑のまん中に水路を通してほしい」
- **学習目標**：二重ループ（線 → 面）、条件分岐（何列目かで水と耕地を使い分ける）
- **雛形**：1 列ぶん（9 マス）の耕地だけを置くループ
- **ヒント**：①何列できた？ x と z のどちらを変える？ ②くりかえしをくりかえしで包む。水かどうかは x で決まる ③3 段インデントの穴あきコード
- **検証**：`on_chat("farm")`／`for` 2 つ以上／`if`／`WATER`・`FARMLAND`／`== 4`（または `!= 4`）／`blocks.place` は 2 回まで／観察「9×9」「まん中 1 列が水」「種をまいて育った」
- **発展**：`x % 9 == 4` で水路 2 本の大きな畑／エージェントに種をまかせる

### Q6【上級】引数つき関数：関数で城を建てよ

- **ストーリー**：かじ屋「4 すみに同じ形の塔。塔のあいだは城壁でつなぐ」
- **学習目標**：引数つきの関数（作り方は 1 つ、場所だけ変える）、座標の計算
- **雛形**：`make_tower(x, z)` の反対側の角が空欄。呼び出しは 1 回だけ
- **ヒント**：①方眼紙に 15×15 の城と塔の位置をかく ②関数は「作り方」。3 マスなら反対側は +2 ③呼び出し 4 回と城壁の fill の穴あき
- **検証**：`on_chat("castle")`／`def make_tower(x, z)`／行頭の `make_tower(` が 4 回以上／`FillOperation.HOLLOW`／`x + 2`／`blocks.fill` 2 回以上／観察「4 すみに塔」「中が空洞」「城壁でつながった」
- **発展**：高さ h の引数を足す／城壁も `make_wall` 関数に／胸壁（ギザギザ）

## v0.2 追加：Google ログイン＋Firebase 保存

| 項目 | 内容 |
|---|---|
| ホスティング | Firebase Hosting（`next build` の静的書き出し `out/`）。GitHub Actions で main への push ごとに自動公開 |
| ログイン | Firebase Authentication（Google）。いまは Google アカウントならだれでも可。`firestore.rules` の `allowedDomains()` と `NEXT_PUBLIC_ALLOWED_EMAIL_DOMAIN` でドメインを絞れる（画面側チェック＋セキュリティルールで強制） |
| 初回登録 | クラス・出席番号・ニックネーム。端末に残っていたローカル進捗は引き継ぎ |
| 保存 | Firestore `users/{uid}`（進捗）＋ `users/{uid}/events`（学習ログ：受注・ヒント・失敗・クリア）。オフラインキャッシュ有効で、Wi-Fi が切れても再接続時に送信 |
| 先生 | Firestore `teachers/{email}` に登録された人。全生徒の閲覧・模範解答表示・`/teacher` 画面（クエスト別クリア数、ヒント段階の分布、声かけ候補、CSV） |
| 権限 | 生徒＝自分のデータのみ読み書き（削除不可）、先生＝閲覧のみ、学習ログ＝追記のみ。`tests/firestore.rules.test.mjs` で検証 |

**既知の限界**：EXP 等の計算はブラウザ側で行うため、技術的には生徒が値を書き換えられる（ルールで型と範囲だけ制限）。成績に直結させる場合は Cloud Functions で報酬計算をサーバー側に移す。
